# Deploying project-tutor for free

This app is five services, not one: the API, the web app, Postgres, MongoDB, and Redis. Each goes on a different free provider — no single platform hosts all of it for free. None of these require a credit card.

| Service                            | Provider                                                      | Free tier                                            |
| ---------------------------------- | ------------------------------------------------------------- | ---------------------------------------------------- |
| API (Express + Socket.IO + BullMQ) | [Render](https://render.com)                                  | Free web service — **sleeps after 15 min idle**      |
| Web (Next.js)                      | [Vercel](https://vercel.com)                                  | Free — no sleep                                      |
| PostgreSQL                         | [Neon](https://neon.tech)                                     | Free — 0.5GB, compute auto-suspends after 5 min idle |
| MongoDB                            | [MongoDB Atlas](https://www.mongodb.com/cloud/atlas/register) | Free M0 cluster — 512MB, no auto-pause               |
| Redis                              | [Upstash](https://upstash.com)                                | Free — 10k commands/day                              |

**The one real tradeoff**: Render's free web service sleeps after 15 minutes with no traffic, and cold-starts in ~30–50s on the next request. While asleep, the background jobs this app relies on (class reminders, the no-show nudge job, contract-termination finalization) don't run — they only fire when the service happens to be awake. See "Keeping it awake" at the bottom if that matters to you.

## 1. MongoDB Atlas

1. Sign up at [mongodb.com/cloud/atlas/register](https://www.mongodb.com/cloud/atlas/register) (Google/GitHub sign-in is fastest).
2. Create a free **M0** cluster (any region close to you).
3. Under **Database Access**, create a database user with a password (not your Atlas login).
4. Under **Network Access**, add `0.0.0.0/0` — Render's free tier uses dynamic IPs, so you can't whitelist a specific one.
5. Click **Connect → Drivers**, copy the connection string. It looks like:
   `mongodb+srv://<user>:<password>@cluster0.xxxxx.mongodb.net/project_tutor?retryWrites=true&w=majority`
   Make sure the database name is `project_tutor` (add it before the `?` if it's missing).

## 2. Neon (Postgres)

1. Sign up at [neon.tech](https://neon.tech).
2. Create a project (any region).
3. Copy the connection string from the dashboard — it looks like:
   `postgresql://<user>:<password>@ep-xxxxx.neon.tech/neondb?sslmode=require`
   Rename the database to `project_tutor` in the Neon dashboard, or just keep whatever name it gives you and use that same string consistently.

## 3. Upstash (Redis)

1. Sign up at [upstash.com](https://upstash.com).
2. Create a Redis database (any region — pick one close to your Render region for lower latency).
3. Copy the **`rediss://`** connection string (the TLS one — note the extra `s`). ioredis and BullMQ both auto-detect TLS from that URL scheme, so no code changes are needed.

## 4. Render (API)

1. Push this repo to GitHub if it isn't already.
2. On [render.com](https://render.com), **New → Blueprint**, connect the repo. Render will detect `render.yaml` at the repo root and pre-fill the service.
3. Render will ask you to fill in the env vars marked `sync: false` in `render.yaml`:
   - `DATABASE_URL` → the Neon connection string
   - `MONGODB_URI` → the Atlas connection string
   - `REDIS_URL` → the Upstash `rediss://` string
   - `CORS_ORIGIN` → leave as `http://localhost:3001` for now, you'll update it after step 5
   - `SUPER_ADMIN_PASSWORD` → a real password of your choosing, used once to seed the super admin account
   - `CLOUDINARY_CLOUD_NAME` / `CLOUDINARY_API_KEY` / `CLOUDINARY_API_SECRET` → from your Cloudinary dashboard (used for avatar/document uploads)

   `JWT_SECRET` and `JWT_REFRESH_SECRET` are auto-generated by Render — you don't need to set those.

4. Deploy. The build step runs `prisma migrate deploy` automatically, so the Neon database gets its schema on first deploy.
5. Once live, copy the Render URL (`https://project-tutor-api-xxxx.onrender.com`) — you'll need it in step 5.

### OTP delivery — email via Resend

Regular users log in with phone + email, and the OTP is sent to that email (not SMS — there's no free-forever SMS gateway, so this avoids a per-message cost entirely). Set it up:

1. Sign up at [resend.com](https://resend.com) (free tier: 3,000 emails/month, no credit card).
2. Create an API key (Dashboard → API Keys).
3. On Render, set `RESEND_API_KEY` to that key. No domain verification needed — it sends from Resend's own `onboarding@resend.dev` by default, which works out of the box. (Once you verify your own domain on Resend, set `RESEND_FROM_EMAIL` to send from it instead.)

Without `RESEND_API_KEY` set, the app **refuses to start in production** unless you explicitly set `ALLOW_MOCK_EMAIL=true` — a conscious fallback, not a silent gap. With that flag, OTPs only appear in Render's **Logs** tab (`[EMAIL MOCK] To: ... | Subject: ... | Body: ...`), never actually delivered. Prefer wiring up Resend — it's free and takes two minutes.

Admin login (`/admin/login`, email + password) doesn't need any of this — it works regardless.

### Seed the super admin (one-time)

Render's free tier doesn't include a one-off job runner, so run this **locally**, pointed at the production database:

```bash
cd packages/database
DATABASE_URL="<your Neon connection string>" SUPER_ADMIN_PASSWORD="<same password you set in Render>" pnpm exec tsx src/seed.ts
```

This seeds roles/permissions and the super admin account (`+919999999999` / `superadmin@tutor.com`). It's safe to re-run — it's an idempotent upsert, not a destructive seed like `seed-mongo.ts` (which refuses to run in production entirely — don't run it against Atlas).

## 5. Vercel (Web)

1. On [vercel.com](https://vercel.com), **Add New → Project**, import the same GitHub repo.
2. Set **Root Directory** to `apps/web`. Vercel auto-detects the pnpm workspace and Next.js framework from there.
3. Add an environment variable: `NEXT_PUBLIC_API_URL` = your Render URL from step 4.5 (e.g. `https://project-tutor-api-xxxx.onrender.com`).
4. Deploy. Copy the resulting Vercel URL (`https://your-project.vercel.app`).

## 6. Close the loop: update CORS

Go back to Render → your service → **Environment**, set `CORS_ORIGIN` to your actual Vercel URL (e.g. `https://your-project.vercel.app`), and if you also want to keep testing against production from your local machine, comma-separate it: `https://your-project.vercel.app,http://localhost:3001`. Save — Render redeploys automatically.

Your app should now be live end-to-end: Vercel → (rewrite proxy) → Render → Neon / Atlas / Upstash.

## Keeping the API awake (optional)

Render's free tier sleeping is the deliberate tradeoff for it being free. If you want the background jobs (class reminders, no-show nudges, contract-termination finalization) to actually run on schedule rather than only when someone happens to be using the site, set up a free uptime monitor (e.g. [UptimeRobot](https://uptimerobot.com), free tier) to `GET` your `/health` endpoint every 10 minutes. This is a widely-used community workaround, not an official feature — Render could change how it handles this in the future, and it does mean the service never actually gets to rest. If the job timing isn't critical to you, it's simpler to just accept the sleep.

## What's not covered here

- **Custom domains** — both Render and Vercel support them free; add them after the above is working.
- **Admin/report moderation, payment dispute review** — these are manual, in-app admin workflows (no separate infra needed).
- **Scaling past the free tier** — Neon, Atlas, and Upstash free tiers cap out at the sizes above; Render's free plan has no auto-scaling. Fine for a demo or early users, not for real production load.
